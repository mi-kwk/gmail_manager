# 検証結果（2026-10-19）

## 実施したこと

実Gmail・利用者のメールデータには接続せず、独立した一時フォルダーと通信の代替実装で検証しました。

- 既存17項目: アカウント識別、削除保護、バックアップ、本文・添付表示など
- 5,000件の保存・読込と送信元完全一致の絞り込み（2,500件一致）
- 1,000件の一括アーカイブ、進捗と永続化された履歴の全件整合
- 50件の区切りを越えた51件目でキャンセルし、残り69件を未処理で保持
- ラベル指定とローカル結果・履歴の整合
- バックアップ待ち・実行中・失敗・完了のすべてで削除保護
- 差分履歴の再起動回復（成功・結果不明・未処理の区別）
- キャンセル後も送信済みリクエストの完了を待つ動作
- 操作の二重実行の拒否
- 対象メール列挙の途中失敗後にも次の操作を実行できること
- 配布版の6画面描画、送信元絞り込み、チェック対象、本文プレビュー

## 修正

大量操作時に履歴全体を毎回保存していた処理を、メールごとの差分保存へ変更しました。
開始時・終了時の全体保存と差分の整理はトランザクションで行い、途中で終了しても成功・実行中・未処理を復元します。
既存の記録形式は維持し、SQLiteに差分保存用テーブルを追加します。
実行中の結果が分からないまま終了したメールは、再起動後「要確認」とします。
対象の列挙中に失敗すると操作用ロックが残る可能性も修正しました。

## 計測

同一PC上の通信代替実装で測定した参考値です。性能保証値ではありません。

| 対象 | 改善前 | 改善後 |
| --- | ---: | ---: |
| 5,000件の保存・読込・送信元絞り込み | 87 ms | 74 ms |
| 1,000件のアーカイブ相当処理と履歴確認 | 3,571 ms | 798 ms |

実Gmailへの通信、認証、クォータ待ち、大容量添付の取得、実際の画面描画時間はこの計測に含みません。
5,000件を超える性能、長期間の履歴蓄積、複数PCでの動作は未確認です。

## 次に確認すること

実Gmailのテスト用メールを指定したうえで、送信元絞り込みからの削除、重要メール除外、ラベル・アーカイブを確認します。
Google側での元メール削除後の閲覧、通信断時の再試行も実接続での確認が残っています。
この検証で利用者の実メールを変更していません。
